# RemoteMCP v3.0.0 — Production v3

RemoteMCP v3.0.0 is the first formal GitHub release of the production-v3 line.

It packages the hardened self-hosted MCP gateway and routed execution runtime used for bounded, multi-agent, multi-device research workflows while preserving the fail-closed governance model.

## Highlights

- **Durable routed execution** with explicit device → project → task placement.
- **Multi-agent task ownership and leases** with CAS-safe mutation and durable jobs.
- **Per-project workspace isolation**: new managed Git worktrees are deterministically placed under one canonical workspace per project instead of being scattered across a broad research root.
- **Direct Git worktree mutation guards** on managed execution paths; agents must use the RemoteMCP lifecycle rather than creating arbitrary sibling worktrees.
- **Secure local dedicated-node pairing** via `device_pair_local_dedicated_node`.
  - the tool does not accept a pairing code;
  - pairing credentials are derived and consumed inside the gateway process;
  - pairing secrets do not travel through shell arguments, routed jobs, repositories, logs, checkpoints, or lineage;
  - existing paired identities cannot be silently replaced;
  - replay after partial consume is accepted only when the local identity matches the centrally paired device.
- **Execution lifecycle recovery** for infrastructure failures without silently launching replacement scientific jobs.
- **Post-run evidence readback** from declared artifacts without rerunning completed science.
- **Explicit multi-device routing** with preserved device identity and fail-closed OFFLINE/revocation behavior.

## Safety and compatibility

This release stays on the **production schema-v3 family**.

It does **not** enable the newer schema-v4 branch-serial admission work from the development line.

No automatic migration, cancellation, history rewrite, scientific-job relaunch, device replacement, or active-worktree deletion is performed by this release.

Existing legacy managed worktrees remain readable in place. New managed tasks use the canonical project workspace layout.
